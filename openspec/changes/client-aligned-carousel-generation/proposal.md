# Proposal: Client-Aligned Carousel Generation (Structured Style Capture + Background-Only Generation)

## Change ID
`client-aligned-carousel-generation`

## Status
Proposal — DRAFT for owner review. Builds on `content-background-sourcing-policy` (`ClientAesthetic` strategy + `BackgroundSelection`), `content-aesthetic-generation-phase-2` (`ClientAestheticProfile`), and `content-image-generation` (provider-agnostic image gateway, two-step generation, the reserved OQ-7 reference-image slot). Specs and design: TBD after approval.

## Intent / Problem

For `BackgroundSourcingPolicy = ClientAesthetic` clients, feed-carousel content generated by the single-analyzer pipeline does NOT match how the client actually publishes. Concretely: a client whose carousels interleave photographic backgrounds with flat-color slides received an all-flat carousel with ZERO images. The generated package was structurally and visually wrong despite the job completing successfully.

Two independent, code-and-DB-confirmed root causes produce this:

1. **Image generation produces no images (infra/wiring + silent degradation).** The org's `single-analyzer/generate-image` workflow step is config-driven (`platform.organization_workflow_step_configs`) and is routed to a provider whose image client fails silently. Every creative slide therefore degrades to a flat CSS background; the job stays `Completed` with `error_code = null` (silent degradation per the resilience contract). The telemetry that should surface this (`social.integration_execution_attempts`) is empty today, so the failure is invisible. Additionally, `ImageGenerationRequest.Init` (the reference-image conditioning slot "reserved for OQ-7") is ALWAYS null and ignored by `OpenAiImageModelClient`, so even a working provider generates backgrounds from a text prompt only — never conditioned on the client's real creatives.

2. **The client's style structure is neither captured nor applied (harness/capture).** Even with working generation, the pipeline has no representation of the client's photo-vs-flat ratio, interleave pattern, or background↔text color pairing logic. It cannot reproduce a structure it never recorded.

The result is a generated carousel that is the wrong shape (all flat, no photos), with the wrong color assignment (palette by array position, not the client's criterion), and no real image backgrounds — a visible, repeatable misalignment with the client's actual feed.

## Confirmed Product Direction (definition of done)

1. **Background-only generation.** The configured media-generation provider generates ONLY the background of a slide (flat color / decorators / photographic image). Text, `@handle`, logo, and signature are composited by US and stay user-editable — the model NEVER draws text or logos.
2. **Client color-pairing logic.** Background↔text COLOR COMBINATIONS follow the client's observed criterion (it varies per client but has a logic), not random or positional palette assignment.
3. **Client package structure.** Package STRUCTURE matches the client: typical slide count AND the photo-vs-flat-background ratio + interleave pattern.

Cross-cutting constraint: image generation stays PROVIDER-AGNOSTIC and CONFIG-DRIVEN. Request the image from whatever MediaGeneration provider is configured for that stage at the time (OpenAI / Gemini-NanoBanana / claude-p / etc., interchangeable). Pass the client's reference images as visual conditioning when the provider supports image input; degrade to a descriptor prompt otherwise. Validate output against the existing `VisualGuardrailValidator` with a bounded retry.

## Problem (harness capture audit — ranked gaps = requirement backbone)

| Gap | Severity | Direction | What is broken today |
|-----|----------|-----------|----------------------|
| GAP 1 | CRITICAL | #3 structure | Photo-vs-flat ratio + interleave pattern not captured. `ClientAestheticProfile.CreativeSlideIndices` is always null in prod; `CreativeSlideIndexResolver.Resolve(null, N)` hard-defaults to `{1, last}` cap 2; `ClientAestheticStrategy.Plan()` then gives every slide the same background. The multimodal extractor mentions a "slide-mix pattern" but has NO DTO field to store it. |
| GAP 2 | CRITICAL | #2 color | No `{backgroundHex, textHex}` color-pairing concept exists. `CompositionDefaults.ResolvePalette()` assigns colors by array position; brand-manual `ColorRole` and extracted `palette.Role` are never joined into pairings. |
| GAP 3 | HIGH | #1 background | Reference images are archived/stored and sent to the aesthetic extractor and threaded into `ClientAestheticDesignContext`, but NOT passed to the image gateway (`ImageGenerationRequest.Init` always null) — backgrounds are never conditioned on real creatives. |
| GAP 4 | MODERATE | #3 structure | Slide count is computed (`AverageSlidesPerCarousel`) but advisory only; it conflicts with a hardcoded "~3-5 slides" in `CarouselGenerator` and is not enforced. |
| GAP 5 | MODERATE | #1 composition | `ClientOwnAccount.Handle` is not loaded into `BrandSnapshot`; `CarouselVisualComposer` has no `@handle`/signature slot (Story & FeedPost do). |
| GAP 6 | LOW-MOD | structure | Typography Weight/Role is discarded; only the first font at fixed sizes is used. |
| Wiring | CRITICAL | cross-cutting | Config-driven `generate-image` routing must select a REAL media-generation provider that works end-to-end; the currently-silent per-slide image-gen degradation must become observable (today `social.integration_execution_attempts` is empty). |

## Scope

### In Scope (first shippable slice — carousel-first)

- **Capture client package structure (GAP 1, GAP 4).** Add structured fields to the aesthetic profile model + persistence for the photo-vs-flat ratio, interleave pattern, and typical slide count. Populate them from the multimodal extractor (add the missing DTO field). Make `CreativeSlideIndexResolver` consume the captured pattern instead of hard-defaulting to `{1, last}`; make the captured slide count enforce (not merely advise) over the hardcoded `~3-5`.
- **Capture and apply color pairing (GAP 2).** Introduce a `{backgroundHex, textHex}` pairing concept derived from the client's observed criterion (joining brand-manual `ColorRole` and extracted `palette.Role`). Replace positional palette assignment in composition with the captured pairing logic.
- **Condition backgrounds on real creatives (GAP 3).** Pass the client's archived reference images to the image gateway via `ImageGenerationRequest.Init` when the configured provider supports image input; degrade to the existing descriptor prompt otherwise. Validate output against `VisualGuardrailValidator` with a bounded retry.
- **Background-only generation contract (direction #1).** Ensure the provider generates ONLY the background; text/`@handle`/logo/signature are composited by us and stay editable. Add the `@handle`/signature slot to `CarouselVisualComposer` and load `ClientOwnAccount.Handle` into `BrandSnapshot` (GAP 5).
- **Restore observability of degradation (wiring).** Make the per-slide image-gen degradation observable (populate `social.integration_execution_attempts` / equivalent telemetry); ensure a real media-generation provider can be selected for `generate-image` and works end-to-end. Keep silent-degradation behavior (job still completes) but make it VISIBLE.
- **Provider-agnostic, config-driven routing (cross-cutting).** Request the image from whatever MediaGeneration provider is configured for the `generate-image` stage; never hardcode a model/provider.

### Out of Scope (deferred follow-ups)

- **Stories.** Story formats are explicitly out of scope — the client's stories cannot be observed the same way (looser constraints). Feed only.
- **Typography Weight/Role application (GAP 6).** Capturing/applying font weight and role is LOW-MODERATE priority and deferred; only the first-font behavior stays unless trivially co-delivered.
- **New provider adapters.** No new MediaGeneration provider SDK is built; the change reuses the existing provider-agnostic gateway and whatever providers are already wired.
- **Hardcoding any model/provider.** Selecting or pinning a specific image provider in code is an explicit non-goal; routing stays config-driven.

### Scope Boundaries

- Hexagonal: Domain ← Application ← Infrastructure/Api. Supabase/EF/ASP.NET/provider SDKs stay behind ports/adapters; NO provider types in Domain/Application (architecture gate).
- New aesthetic fields are ADDITIVE to the aesthetic profile model + persistence (nullable, reversible).
- The change targets FEED formats (single + carousel), prioritizing carousel for the first slice; Story formats remain untouched.
- Generation responsibility ends at producing a validated background + composition envelope; the studio's editable-text compositing is reused as-is.

## Capabilities

### Modified Capabilities (additive deltas)

- `background-sourcing-policy` / `content-aesthetic-generation`: the `ClientAesthetic` profile gains structured package-structure fields (photo-vs-flat ratio, interleave pattern, enforced slide count) and a `{backgroundHex, textHex}` color-pairing concept; the extractor populates them.
- `content-generation`: `CreativeSlideIndexResolver` and `ClientAestheticStrategy.Plan()` consume the captured structure instead of the `{1, last}` default; composition applies the captured color pairings instead of positional palette; `CarouselVisualComposer` gains an `@handle`/signature slot.
- `image-generation`: the image gateway receives the client's reference images via `ImageGenerationRequest.Init` (image-conditioning, OQ-7 realized) when the provider supports it, with descriptor-prompt fallback and guardrail-validated bounded retry; background-only generation contract enforced.
- `integrations` / observability: per-slide image-gen degradation becomes observable via the execution-attempt telemetry; `generate-image` routing confirmed end-to-end against a real configured provider.

## Approach

Close the ranked gaps in two coordinated tracks while keeping provider routing config-driven.

**Capture track (harness).** Extend the aesthetic profile model and persistence with additive, nullable fields for package structure (photo-vs-flat ratio, interleave pattern, typical slide count) and color pairing (`{backgroundHex, textHex}` derived from the client's observed criterion joining brand-manual `ColorRole` + extracted `palette.Role`). Add the missing DTO field so the multimodal extractor can write the slide-mix pattern it already detects.

**Apply track (generation + composition).** Make `CreativeSlideIndexResolver` and `ClientAestheticStrategy.Plan()` consume the captured structure so slides get the correct photo-vs-flat assignment and interleave; enforce the captured slide count over the hardcoded `~3-5`. Replace positional palette assignment in `CompositionDefaults.ResolvePalette()` with the captured pairings. Add the `@handle`/signature composition slot to `CarouselVisualComposer` and load `ClientOwnAccount.Handle` into `BrandSnapshot`.

**Background-conditioning + observability.** Thread the client's archived reference images into `ImageGenerationRequest.Init` so the configured provider conditions backgrounds on real creatives when it supports image input, degrading to the descriptor prompt otherwise; validate against `VisualGuardrailValidator` with a bounded retry. Enforce background-only generation (no text/logos drawn by the model). Restore observability of the currently-silent per-slide degradation by populating the execution-attempt telemetry, and confirm a real media-generation provider can be selected for `generate-image` end-to-end. All image requests resolve the provider from config at call time — no hardcoded model/provider.

## Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Provider image client still fails after wiring fix (silent degradation persists) | Medium | Restore execution-attempt telemetry FIRST so failures are visible; verify end-to-end against a real provider before relying on it. |
| Reference-image conditioning unsupported by some configured providers | Medium | Capability-detect image input; degrade to descriptor prompt; keep provider-agnostic contract — no hardcoding. |
| Captured structure is sparse/empty for a client (cold start) | Medium | Keep nullable fields; fall back to current default behavior when structure is absent; treat capture as progressive. |
| Color-pairing criterion is ambiguous or varies more than observed | Medium | Derive pairings from joined `ColorRole` + `palette.Role`; flag the exact joining rule for spec/design (OQ). |
| Slide-count enforcement breaks existing packages relying on `~3-5` | Medium | Enforce only when captured count exists; otherwise keep current behavior; cover with tests (Strict TDD). |
| Aesthetic profile contract change ripples to extractor + persistence | Medium | Additive nullable fields only; migrate non-destructively; update extractor DTO in the same change. |
| Architecture leak (provider SDK types reaching Domain/Application) | Medium | Keep provider concerns behind the existing image gateway port; bytes/reference-only contract; architecture gate. |

## Rollback Plan
- All new aesthetic fields are additive and nullable; dropping them reverts to current `{1, last}` / positional-palette behavior with a non-destructive migration.
- Reference-image conditioning is gated on a configured image route + provider image-input support; absent either, the existing descriptor-prompt path runs unchanged.
- Slide-count enforcement and color-pairing application are gated on captured structure existing; with no captured data the current defaults run.
- Telemetry restoration is observational and reversible; it does not change job-completion semantics (degradation stays non-fatal, just visible).
- The `@handle`/signature slot and `BrandSnapshot.Handle` load are additive composition changes; removing them reverts to the current carousel composition.

## Success Criteria

- [ ] The generated package's slide count matches the client's typical count (enforced, not advisory; the hardcoded `~3-5` no longer overrides it).
- [ ] Background↔text colors follow the captured `{backgroundHex, textHex}` pairing criterion, not array position.
- [ ] Creative slides render a REAL background conditioned on the client's reference images when the configured provider supports image input; otherwise a descriptor-prompt background, validated by `VisualGuardrailValidator` with bounded retry.
- [ ] The model generates ONLY backgrounds; text, `@handle`, logo, and signature are composited by us and remain editable in the Content Studio; `CarouselVisualComposer` has an `@handle`/signature slot.
- [ ] Per-slide image-gen degradation is observable in execution-attempt telemetry; a silent failure is no longer invisible.
- [ ] Image provider is resolved from config at call time — no hardcoded model/provider; Stories untouched.
- [ ] No provider types leak into Domain/Application; all MUST gates pass (`pwsh -File scripts/gates/Run-Gates.ps1`); Strict TDD — capture/resolver/pairing rules tested before implementation.

## Open Questions (for spec/design)
- **OQ-1 — Structure representation.** Exact shape for the captured photo-vs-flat ratio + interleave pattern (per-index flags vs. ratio + pattern descriptor) and how `CreativeSlideIndexResolver` maps it to a variable slide count.
- **OQ-2 — Color-pairing derivation.** The precise rule joining brand-manual `ColorRole` and extracted `palette.Role` into `{backgroundHex, textHex}` pairings; how the "client's observed criterion" is encoded when it varies.
- **OQ-3 — Slide-count enforcement.** Hard-enforce the captured count vs. clamp to a captured range; behavior when requested length conflicts with the client's typical count.
- **OQ-4 — Reference-image selection.** Which/how many archived creatives to pass as `Init` conditioning per slide; cost/latency cap; provider-capability detection mechanism.
- **OQ-5 — Cold-start fallback.** Default behavior when captured structure/pairing is absent for a client (progressive capture) — keep current defaults vs. a smarter heuristic.
- **OQ-6 — Telemetry scope.** Exact execution-attempt rows/fields to populate for per-slide image-gen degradation, and whether degradation should additionally raise a non-fatal `error_code` while keeping the job `Completed`.
- **OQ-7 — Carousel-first vs. single-format parity.** Whether the first slice covers single-image feed posts too or carousel only, given the shared `ClientAesthetic` surface.
