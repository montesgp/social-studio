# Proposal: Content Background Sourcing Policy

## Change ID
`content-background-sourcing-policy`

## Status
Proposal — defines a per-client background sourcing policy (decision tree), the carousel-coherence fix, the structured color-role scale, and advisory concision. Specs and design: TBD.

## Intent

Content generation has two defects and one missing capability:

1. **Incoherent carousel backgrounds.** `BackgroundSelector.Select()` runs INDEPENDENTLY per slide inside the per-slide loop (`ContentGenerationJobProcessor.cs:315`), with a second uncoordinated call site in `CarouselVisualComposer.cs:61`. A carousel's slides can therefore each resolve a different background — there is no shared, carousel-level decision.
2. **No per-client background policy.** The 3-tier model (ForcedDefault → References → Creative) is implicit in which templates exist; there is no client-level concept of HOW backgrounds should be sourced. The owner wants this configured per client in the client ABM, driven by a decision tree.
3. **Backgrounds and copy ignore brand scale + concision.** `EfClientBrandSnapshotLoader.cs:102` drops `ColorEntry.Role`, so the AI designer never receives palette prevalence/weighting. Copy generators carry no concision guidance, so social formats get too much text.

## Problem

- Carousel coherence is broken by per-slide background resolution; the two call sites must be reconciled into one shared plan.
- `BackgroundSelector` is a static, closed 3-case selector — not extensible (CASE D needs new strategies without touching existing ones).
- `BrandManualSnapshot.ColorPalette` is hex-only (`IReadOnlyList<string>`); role/ordering is silently discarded, blocking CASE B weighting.
- No length/concision directive exists on any copy generator field.

## Decision Tree (behavior per case)

- **CASE A — Client-defined background SET.** Carousels are generated by combining the client's backgrounds `[bg1..bgN]`; singles pick from `[bgA..bgN]`. 1 background → strict (always that one). Multiple → varied but within a consistent style family. Selection for a carousel is COHERENT across its slides (one shared plan), not re-decided per slide.
- **CASE B — Fully AI-generated** (single + carousel) honoring the brand-manual palette AND its SCALE: the color Role ordering (primary/secondary/accent/neutral) determines prevalence/weighting fed to the AI designer.
- **CASE C — Client's known aesthetic** from their last ~20 feed posts, reusing the existing profile-analysis capability. SEAM-READY ONLY: implemented using the existing TEXT descriptors (`ProfileAiAnalysis.DetectedBackgroundImages`) as aesthetic guidance to the AI designer; real post-image URLs are deferred (see Out of Scope).
- **CASE D — Future cases.** Does not exist yet; the design MUST be extensible (strategy/policy pattern, open/closed) so a new case plugs in without reworking A/B/C.

## Scope

### In Scope

- **Per-client policy** (`BackgroundSourcingPolicy`) on the `Client` domain aggregate (nullable). Existing clients default to current 3-tier/legacy behavior via a migration default.
- **`IBackgroundSourcingStrategy` port** (Application) with one strategy per case A/B/C, resolved by the client's policy; `BackgroundSelector` becomes the legacy/CASE-A adapter. CASE D = add a strategy without touching existing ones.
- **Carousel-coherence fix**: compute ONE shared `CarouselBackgroundPlan` BEFORE the slide loop in `ContentGenerationJobProcessor` and pass it to every slide; reconcile the second call site in `CarouselVisualComposer`.
- **Structured color-role scale**: `ColorEntry.Role` becomes a structured, ordered model (enum Primary/Secondary/Accent/Neutral + rank/order). The ordering is propagated through `BrandManualSnapshot` (fixing the loss at `EfClientBrandSnapshotLoader.cs:102`) and into the AI designer prompt as a prevalence/weighting signal. Requires a migration.
- **Advisory concision (prompt-only)**: add firm concision rules to copy-generator prompts (singles = super-summary; carousels = one concept molded across slides, conceptual, per-slot length/line guidance), LOG violations, do NOT hard-reject AI output. Bump `ContentGenerationPromptVersions`.
- **ABM surface**: expose the policy in the client admin API + Next.js client ABM UI; expose the color-role ordering in the brand-manual editor.

### Out of Scope (deferred)

- **CASE C full image pipeline.** Bringing REAL post-image URLs requires extending the Apify scraper; deferred as a follow-up. Only the text-descriptor seam ships now.
- **Hard concision validation.** No new length validator; concision is advisory/logged only.
- **CASE D concrete strategies.** Only the extensibility seam, not new cases.

### Scope Boundaries

- Policy is a **client-level** attribute (applies regardless of which brand-manual version is active), not a manual-version attribute.
- Provider-specific concerns (EF Core, Apify, AI providers, ASP.NET) stay behind ports/adapters and MUST NOT leak into Domain/Application. The strategy port lives in Application; AI/Apify wiring stays in Infrastructure adapters.
- Background selection responsibility ends at producing a `BackgroundSelection`/`CarouselBackgroundPlan`; rendering/guardrails are reused as-is.

## Capabilities

### New Capabilities

- `background-sourcing-policy`: per-client background sourcing strategy (decision tree A/B/C, extensible to D), carousel-coherent background planning, and the policy ABM surface.

### Modified Capabilities (additive deltas)

- `content-generation`: carousel background coherence (shared plan over per-slide selection); structured `ColorEntry.Role` scale propagated to `BrandManualSnapshot` and the AI designer; advisory concision rules + prompt-version bumps.
- `profile-analysis`: read seam exposing `ProfileAiAnalysis.DetectedBackgroundImages` (text descriptors) as CASE C aesthetic guidance (read-only; no analysis behavior change).

## Approach

(Approach 1 from exploration — intent level.) Introduce `BackgroundSourcingPolicy` on `Client` (nullable; migration default = legacy 3-tier). Add an `IBackgroundSourcingStrategy` Application port with one implementation per case, resolved by the client's policy; the existing `BackgroundSelector` becomes the legacy/CASE-A adapter. In `ContentGenerationJobProcessor`, resolve the strategy and compute a single `CarouselBackgroundPlan` BEFORE the per-slide loop, then feed the per-slide selection from that plan; reconcile `CarouselVisualComposer`'s redundant call so both sites read the same plan. Make `ColorEntry.Role` a structured ordered model and thread `(Hex, Role, rank)` through `BrandManualSnapshot` into the AI designer guidance. Add advisory concision directives to the copy-generator prompts and bump prompt versions. Surface the policy and color-role ordering in the API + web ABM.

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Carousel coherence regression when moving to a pre-loop shared plan (two call sites) | High | Single `CarouselBackgroundPlan` computed once; both `ContentGenerationJobProcessor` and `CarouselVisualComposer` read it; cover with tests before refactor (Strict TDD). |
| `BrandManualSnapshot.ColorPalette` contract change (exploration flags it as a frozen, hex-only contract) | High | Treat as a deliberate breaking change; update ALL consumers (guardrail palette check, template markup builder, AI designer) in the same change; spec the new shape explicitly. |
| Prompt-version bump token spike (invalidates cached AI outputs) | Medium | Bump only the touched format versions; accept first-run cost; advisory-only avoids re-reject loops. |
| Apify actor uncertainty for CASE C (NOT confirmed the configured actors can return post background images) | Medium | CASE C ships text-descriptor seam only; real image URLs are an explicit non-goal and OPEN dependency to investigate before committing the full image path. |
| Policy default for existing clients | Medium | Migration default maps `UNSET`/null to current 3-tier behavior; define mapping explicitly in spec. |
| `ResolveEnforcedBackground()` hard-enforces References[0] | Medium | CASE A set-rotation must change this first-entry-wins rule; flag for design. |

## Rollback Plan

- Policy column is additive with a default mapping to legacy behavior; dropping it restores current selection.
- Strategy resolution falls back to the legacy `BackgroundSelector` adapter when policy is `UNSET`/null — disabling strategies reverts behavior.
- The structured-role change is the only non-trivial contract change; it is gated behind a migration and the snapshot shape — reverting requires reverting the snapshot consumers together (called out as a coordinated rollback unit).
- Concision is prompt-only: reverting the prompt-version bumps restores prior copy behavior with no schema impact.

## Dependencies

- Existing profile-analysis pipeline (`ProfileAiAnalysis.DetectedBackgroundImages`) for CASE C text descriptors — read-only.
- Existing rendering/guardrail/AI-designer stack (`AiVisualDesigner`, `VisualGuardrailValidator`) — extended, not replaced.
- New EF migration (policy column + structured color role).
- OPEN dependency (deferred): whether current Apify actors can return post-image URLs for CASE C's full path — investigate before committing.

## Success Criteria

- [ ] A client's `BackgroundSourcingPolicy` is set in the ABM (API + web); existing clients keep current 3-tier behavior by default.
- [ ] A generated carousel uses ONE coherent background plan across all its slides (no per-slide divergence); both call sites read the shared plan.
- [ ] CASE B feeds the structured color-role ordering (Primary/Secondary/Accent/Neutral + rank) into the AI designer as a prevalence/weighting signal; `ColorEntry.Role` is no longer dropped at the snapshot boundary.
- [ ] CASE C strategy passes `DetectedBackgroundImages` text descriptors as aesthetic guidance; no Apify change is made.
- [ ] Adding a hypothetical CASE D strategy requires NO change to A/B/C (open/closed verified).
- [ ] Copy generators carry advisory concision directives; violations are logged, never hard-rejected; prompt versions bumped.
- [ ] Provider types (EF, Apify, AI) do not leak into Domain/Application (architecture gate green).
- [ ] All MUST gates pass (`pwsh -File scripts/gates/Run-Gates.ps1`); Strict TDD — domain/application rules tested before implementation.

## Open Questions (for spec/design)

- **OQ-1** — CASE A multi-background selection: deterministic (seeded by job/date) or truly random within the style family? What guarantees "consistent style family"?
- **OQ-2** — Color-role representation in the UI: enum Primary/Secondary/Accent/Neutral + separate rank int, or a single ordered list? How is the scale entered/edited?
- **OQ-3** — CASE C: confirm text-descriptor guidance is acceptable for the MVP; record the Apify-actor image-URL investigation as the follow-up trigger.
- **OQ-4** — Policy placement: directly on `Client` vs. a new `ClientGenerationPolicy` sibling aggregate (more extensible for CASE D, more ceremony).
- **OQ-5** — Discriminated-union impact: add a `BackgroundSelection.ClientAesthetic(descriptors)` variant / `CarouselBackgroundPlan` type, or thread aesthetic/plan data through a separate channel?
- **OQ-6** — Policy interaction with regeneration/`RegenerationObjection`: does a retry honor the same policy or re-derive the plan?
